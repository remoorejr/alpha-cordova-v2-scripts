# 📘 Alpha Cordova Developer Guide (v2.8.0 Turbo Edition)

This guide provides a deep dive into the automation architecture of the Alpha Cordova Suite. Version 2.8.0 focuses on **Consolidated Stability**, **Ultra-Fast Turbo Sync Performance**, and **Zero-Touch Release Automation**.

---

## 🏗️ Architecture Overview
The suite uses a **Containerized Build Pattern**. By wrapping the Android SDK, Gradle, and Cordova inside a Docker container, we eliminate "it works on my machine" issues caused by local environment drift.

### The "Brain": `release-build.ps1`
The PowerShell engine handles the orchestration between your Windows host and the Linux container. It performs several critical tasks:
1.  **Sanitization:** Preparing the host filesystem for Docker access and aligning home paths.
2.  **Versioning:** Parsing `config.xml`, auto-incrementing `versionCode`, and updating Git tags.
3.  **Changelog Management:** Scraping Git logs to automatically update `CHANGELOG.md`.
4.  **Turbo Execution:** Bypassing standard wrappers to execute direct, highly optimized native Gradle builds.
5.  **Deployment & Export:** Interfacing with the host-side `adb` to force-push signed artifacts to physical hardware and exporting accessible artifacts to the project root.

## 🛡️ The Permission Shield & Security Bridge
One of the primary challenges in WSL2/Docker development is the mismatch between Windows ACLs and Linux UIDs. The engine implements a dual-layer shield:

### 1. HOME Redirection
We force the container's `$HOME` to the project root (`/home/cordovauser/app`). This prevents the container from trying to write to protected or non-existent system folders in the WSL backend.

### 2. The ".bat" Security Wrapper
To resolve `SecurityError: UnauthorizedAccess` issues for team members, we use Batch wrappers (e.g., `Verify-Environment.bat`). These files use a specific flag to bypass Windows execution policies for the session without requiring system-wide changes:
```batch
powershell -ExecutionPolicy Bypass -File .\release-build.ps1
```

### 3. `.config` Sanitization
Many Node.js tools (like Cordova and Insight) try to write telemetry to `~/.config`. If this folder is owned by Windows "System," the build crashes. The script now force-clears and re-grants `Everyone:F` permissions to a local `.config` directory before every build.

## ⚡ Ultra-Fast Turbo Sync Engine
To achieve near-instant UI updates (~2 seconds), v2.8.0 utilizes **Named Volume Shadowing** combined with **Direct Gradle Execution** and **Smart Asset Detection**.

### 1. Named Volume Shadowing
Standard "Bind Mounts" (mapping `C:\project` to `/app`) are slow for the thousands of small files generated by Gradle and NPM. We map **Named Volumes** directly onto sub-folders *inside* the project root:
* `gradle_cache` -> `/home/cordovauser/app/.gradle`
* `npm_cache`   -> `/home/cordovauser/app/.npm`

Docker "shadows" these folders. The tools believe they are writing to the project directory, but the data is intercepted and stored in the **Linux-native EXT4 filesystem**, bypassing the slow Windows/WSL file-system bridge.

### 2. Smart Asset Detection
When running Option 2 (Turbo Sync), the engine compares the "Last Modified" timestamp of the newest file in your `www/` folder against the Android platform assets. It intelligently skips the file copy process if no code changes are detected, saving critical I/O time.

### 3. Direct Gradle Execution
Turbo Sync completely bypasses the slow `cordova build` wrapper. It directly invokes `./gradlew assembleDebug` using highly optimized flags (`--parallel`, `--build-cache`, `--daemon`, `--configure-on-demand`). This allows Gradle to hit the cache perfectly, skipping up to 95% of the build tasks for pure UI updates.

## 📈 Advanced Release Automation
The engine introduces "Zero-Touch" management for production deployments:

* **Version Bumping:** Automatically reads `config.xml`, increments the `version` string (e.g., 2.3.0 -> 2.4.0), and bumps the `android-versionCode` (required for Google Play).
* **Git Log Injection:** During a release build, the script scrapes all commit messages since the last Git tag and prepends them to the top of `CHANGELOG.md` with a datestamp.
* **Automatic Tagging:** Once a build is successful, the script automatically runs `git commit` and `git tag` to lock the release into your repository history.

## 🔊 Audio Notifications 
The build engine includes a `[System.Console]::Beep` audio feedback system, allowing for "eyes-free" monitoring of the build process across Windows and WSL environments.

* **Sync Chime (Short Double High-Tone):** Plays when code changes are successfully detected and synced.
* **Success Melody (Rising Three-Tone):** Plays when a build finishes and successfully installs to the device.
* **Error Alarm (Low Double-Tone):** Plays if a build step fails, ADB deployment fails, or the container crashes.

**Benefit:** This allows developers to multitask or step away from their workstations, knowing they will be audibly alerted to exact pipeline events.

## 📦 Artifact Export & Deployment
Google Play requires **Android App Bundles (`.aab`)**, but rapid local development requires **APKs**. The engine handles this via an intelligent deployment block:

1.  **Dynamic Discovery:** After a build, the script recursively hunts down the newest `.apk` file generated by Gradle, regardless of folder structure changes.
2.  **Artifact Export:** The discovered APK is automatically copied out to a `debug/` folder in the project root (named `app-debug.apk`) for easy access via Windows Explorer.
3.  **Airtight Deployment:** The script bypasses Cordova's internal deployment logic and uses the **host-side `adb`** directly. By passing the `-r` (replace), `-d` (downgrade), and `-t` (test package) flags, it forces Android to overwrite existing applications, permanently eliminating debug signature mismatch errors.

## 🔐 Signing Configuration (`build.json`)
Standardizing on `build.json` is required for production builds. Unlike `.properties` files, JSON allows the Cordova CLI to accurately parse complex signing arguments for both Bundles and APKs.

**Example `build.json`:**
```json
{
    "android": {
        "release": {
            "keystore": "alpha-release.keystore",
            "storePassword": "your_password",
            "alias": "your_alias",
            "password": "your_password",
            "keystoreType": "jks",
            "packageType": "bundle"
        }
    }
}
```

## 🔍 Troubleshooting
| Issue | Cause | Solution |
| :--- | :--- | :--- |
| `EACCES: permission denied` | root-owned cache folders. | Run: `docker compose run --rm --user root builder chown -R 1000:1000 /home/cordovauser/app/.npm /home/cordovauser/app/.gradle` |
| `WSL 1 detected` | Incompatible filesystem. | v2.8.0 REQUIRES WSL 2. Run `wsl --set-default-version 2`. |
| `SecurityError` | PS Execution Policy. | Always launch using the provided `.bat` wrapper files. |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | Signature mismatch | Delete the app manually from the physical device once, then run Turbo Sync. Future updates will overwrite perfectly. |
| Slow Build Speeds | Cache Mismatch. | Ensure `.gradle` and `.npm` folders are deleted from the Windows host so the Named Volumes can take over. |
